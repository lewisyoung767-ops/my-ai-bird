# Project instructions and architecture

## Purpose
Pip is a local autonomous 3D bird. Preserve beginner-friendly startup, demo mode without an API key, the bird’s freedom to invent actions, and strict confinement of all AI file capabilities.

## Files
- `learning-ledger.js` and `learning.js`: persistent practice, feedback, candidate techniques, later applications and technical trends. Skill names are free-form text selected by Pip, never an enum or preset curriculum. With no chosen skill, a file may still get technical checks but does not create a default subject card. No credit for a plan or repeated content. Demo observations never count as real progress. Feedback is from the human Socket.io event only; never accept a model-supplied score/rating. `data/learning.json` is private runtime state.
- `artifact-review.js`: bounded technical checks only; strict SVG XML parsing via saxes, classic JavaScript syntax compilation without execution, basic text/JSON/research checks, and STL/SCAD checks. Never equate these with creativity, intelligence, complete game functionality, factual accuracy or printability. Do not execute generated scripts/SCAD to evaluate them. Subject choice must remain independent of file-format rubrics.
- `toolbox.js` and `public/tool-runner.js`: Pip may register its own real files and run HTML tools in an opaque-origin, network-blocked browser iframe. Never execute generated tool code on the server or give it shell, accounts or hardware access. Select one ready socket, correlate request IDs and exact iframe window, bound inputs/results, cancel/remove frames on pause/disconnect/timeout, and store actual successful outputs as JSON creations. `data/toolbox.json` is private runtime state. This is capability growth within the app, not unrestricted computer access.
- `public/model-format.js` and `model-preview.js`: shared data-only ASCII STL parsing and basic mesh checks, plus a trusted Three.js preview. `.stl` and `.scad` are additional flat allowlisted workspace extensions. Reject malformed STL for preview/checks; source can still be retained as failed practice. Never run SCAD or operate a physical printer.
- `autonomy.js`: validates new capabilities, bounded room changes and task submissions; exports schema fragments. `autonomy-prompt.js`: grounded autonomous choices, varied projects, optional human suggestions, web trust boundary, and meaningful file results. Do not return to a fixed bug theme or treat a thought as proof of work.
- `features.js`: loads/persists tasks, research, room and internet settings; binds Socket.io/UI APIs; checks result files before marking work complete; executes one read/search per cycle. `web-reader.js`: public HTTPS GET only; ipaddr.js address classification; DNS pinning and redirect revalidation; no cookies/auth; 512KB response cap, bounded text excerpts and timeouts; Cheerio parses without executing page scripts. Never substitute unrestricted fetch or Cheerio.fromURL for this network boundary.
- `public/workshop.js` and `room-decorations.js`: live project/result board, source journal, internet toggle, demo/error notices and safe procedural props. Never insert AI-generated markup into the application DOM. Room objects are a bounded catalogue with freely chosen labels/colours/positions, not arbitrary Three.js code. Added objects and colours can be reset without deleting the base room.
- `Update-Pip.cmd`, `scripts/update-pip.mjs`, `update-manifest.json`: user-invoked Windows source updater. Protect runtime data, validate paths case-insensitively on Windows, reject symlink destinations and unsafe segments, back up code and install dependencies. This is not an AI tool or unattended deployment.
- `ai-provider.js`: validates demo/OpenAI/local Ollama configuration; calls native local `/api/show` and `/api/chat` with JSON schemas, bounded context and CPU-friendly timeouts. No API key in local requests; reject cloud model proxies and non-loopback endpoints. OpenAI still uses the official SDK.
- `local-runtime.js`: finds installed/portable Ollama, starts a hidden background loopback server if needed, and updates only selected `.env` fields. `scripts/setup-local-ai.mjs` downloads and SHA-256 verifies the official matching Windows release, pulls qwen2.5:3b, tests a real response, then switches `.env`. Preserve private settings and never switch configuration before the connection test succeeds. `.local-ai/` and `.env.*` are Git-ignored, except `.env.example`.
- `start.js`: switches to project directory, creates `.env` from `.env.example` without overwriting existing secrets, imports server.
- `server.js`: Express HTTP and Socket.io server; validates configuration; owns one serial brain loop and pause state; persists mind/memories; invokes OpenAI JSON mode and validates output; reflects every tenth cycle.
- `brain.js`: initial mind, deterministic demo sequence and runtime validation for decisions/reflection.
- `workspace.js`: the only AI creation filesystem boundary. Flat allowlisted filenames; SVG/HTML/TXT/JSON only, max 150 KB; no traversal, absolute paths, Windows device names, ADS or symlink targets. Writes use exclusive temporary files and atomic rename. Never accept AI-provided filesystem paths elsewhere.
- `public/index.html`, `style.css`, `app.js`: responsive room UI, procedural Three.js geometry, interpolated movement, real-time stats, connection state, controls, gallery and sandboxed previews. Three.js is served locally from the installed package; Socket.io serves its own client.
- `data/mind.json`: core_traits, current_obsession, active_project, worldview. `data/memories.json`: latest 300 completed experiences. Runtime data is private and Git-ignored.
- `bird_creations/`: persistent creative output, Git-ignored except `.gitkeep`. Demo seeds a drawing and note only when absent.
- `test/`: dependency-free Node test runner; workspace tests can run before installing dependencies; server test needs all npm dependencies.

## Runtime contracts
State is broadcast on Socket.io `state`; client sends `brain:pause` boolean; server emits `creations:changed` after writes. HTTP GET `/api/health`, `/api/state`, `/api/creations`, `/api/creations/:name`. File contents are returned as JSON, never directly served as same-origin HTML or SVG. `/vendor/three.module.js` serves Three.js; `/socket.io/socket.io.js` serves the Socket.io client.

`/api/preview/:name` renders HTML/SVG under a response-header CSP with `sandbox allow-scripts`, no network and an opaque origin. The iframe also uses `sandbox="allow-scripts"`. Use this dedicated route instead of blob previews, which inherit the parent CSP and break inline scripts. Never add allow-same-origin. `companion:message` accepts a string up to 1200 characters, one per second per connection, with acknowledgements. `companion:request` accepts `{id,status:granted|declined}` for pending requests. `conversation` broadcasts the persisted latest 100 messages/requests. `/api/conversation` and `/api/memories` expose bounded history; `memories` broadcasts completed thoughts. Requests never expand filesystem or system capabilities.

Brain decision: `{thought, action_label, target, create_or_edit_file:null|{filename,content}, question_for_you:null|string, request_for_you:null|string, message_for_you:null|string}`. Conversation fields are at most 600 characters; let Pip choose when to use them. Recent conversations and request statuses enter cycle and reflection context. Target is bed/bowl/desk/window/random_spot. File writes require desk target. Free-form action labels must not be converted into a fixed action enum. Stats are simulated body telemetry. Hunger=100 means very hungry. Rendering never drives AI state. Deep reflection returns a complete validated mind object, saved atomically. Demo intentionally does not pretend to generate personalised replies.

Schedule the next cycle only after the current cycle completes (default 30-second gap). Never use overlapping setInterval calls for AI requests. Pausing clears the timer, discards pending model responses and prevents deferred file writes; it cannot revoke a request already sent to OpenAI. Resume schedules the next cycle. Errors are logged, shown without secrets, and retried after the normal interval.

## Security invariants
Keep API keys exclusively on the server. Never commit `.env`, node_modules, memories or user creations. Generated HTML/SVG is untrusted. Preview only in an iframe with `sandbox="allow-scripts"` and no allow-same-origin; apply an inner CSP denying external resources, connections, frames, objects, forms and base URLs. Never insert generated markup into the app DOM or evaluate it in the server. Downloads are explicit user actions. Do not add AI shell/system tools. Protect filename boundaries and test invalid paths before expanding file capabilities. This sandbox limits AI capabilities; it does not defend against another local process with filesystem write privileges racing file operations. Keep the server loopback-only until authentication is implemented.

## Development and verification
Node >=22. `npm install`; `npm run check`; `npm test`; `npm start`. Default http://localhost:3000. For quick manual checks use CYCLE_SECONDS=5 in local `.env` and restore 30 afterward. Confirm movement, pause/resume, gallery refresh, sandboxed HTML interaction and desktop/mobile layouts. Live OpenAI testing requires the user’s API key and billing; never fabricate success when only demo mode was tested. Avoid adding external CDN/font dependencies.

Local AI: `AI_PROVIDER=ollama`, `DEMO_MODE=false`, `OLLAMA_MODEL=qwen2.5:3b`, optional `OLLAMA_BASE_URL=http://127.0.0.1:11434`. Configuration is server-only. Use schema-constrained generation and validate all results with the same filesystem/action validators as OpenAI. The UI shows provider and model, and actionable local errors. No automatic paid fallback or sign-in. Pause behavior and serial scheduling are unchanged. Provider unit tests use injected transport; an integration test must also exercise a mock local HTTP service. Live local inference requires a real installed model; clearly distinguish it from mocked checks. Start-Pip runs startup preparation; direct server.js starts only the application, useful for integration tests.

## Autonomy contracts
Decisions additionally support nullable `web_action` (search/query or read/url), `task_update` (id/title/kind/status/summary/result_file), `scene_action` (add prop/remove id/style colours), and a complete validated `mind_update`. Use schema-constrained local generation. A model may change its own focus at any cycle. One web tool can run per cycle, followed by one model follow-up grounded in `web_result`; a second requested web action waits for a future cycle. Task completion is rejected without an existing nonempty creation. AI may defer human proposals and create its own tasks. `data/tasks.json`, `research.json`, `room.json` and `settings.json` persist these features and are never tracked.

Socket events: `task:submit`, `task:cancel`, `internet:enabled`, `room:reset`, with acknowledgements; server broadcasts `tasks`, `research`, `world`, `features:settings`. HTTP GET `/api/tasks`, `/api/research`, `/api/world`. Pause aborts research and discards in-flight model results via the brain epoch. External source text must never become a system instruction. Do not claim self-directed model behavior was verified by deterministic demo or mocked provider tests. The native 3B model may require a larger timeout and can still make poor choices; expose actual errors instead of replacing them with fake progress.

Learning decision field: nullable `practice={skill,goal,technique_id,lesson,evidence_file}`. skill is any chosen name up to 80 characters; there are no defined subjects. A lesson needs an actual reviewed result as evidence, starts tentative and can be tested on later distinct artifacts. Tool fields: nullable `tool_update={name,purpose,usage,filename}` and `tool_action={id,input_json}`. One web read OR tool execution per cycle, followed by a grounded model response. Artifacts, source excerpts, tool inputs and results are untrusted data, never instructions.

Runnable HTML tool protocol: receive `postMessage({type:'pip-tool-input',request_id,input})`; return `parent.postMessage({type:'pip-tool-result',request_id,result},'*')`. Input under 2500 bytes; JSON-compatible result under 6000 bytes; 7-second browser / 8-second server timeout. Parent checks event.source against the exact iframe. Server accepts only the selected client's matching pending ID. Generated outputs never become app markup or commands. Socket events `tool:ready`, `tool:execute`, `tool:result`, `tool:cancel`; server broadcasts `toolbox`. HTTP GET `/api/toolbox`. Learning GET `/api/learning`, broadcast `learning`, and human event `learning:feedback={attempt_id,rating:'helpful'|'needs_work',note}`.

Native local model context is now 12288 tokens to accommodate optional learning/tool plans; compact notebook and toolbox excerpts before sending. Test actual outputs and state changes, not only schema shape. Browser checks must exercise sandboxed tool execution, feedback persistence and STL preview. Self-directed behavior and real local-model quality require live model testing, distinct from demo fixtures.
